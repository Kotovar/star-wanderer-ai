# Мета-прогрессия и достижения

Полная реализация описана поэтапно в `META_PROGRESSION_PLAN.md` (Фазы 1–5) — этот файл фиксирует итоговое поведение системы, а не историю решений.

На старте («Новая игра» с пустым прогрессом) доступны только 2 из 6 шаблонов корабля и 0 из 16 доктрин/модификаторов. Остальное открывается игрой: корабли — за общий прогресс (сколько забегов сыграно/выиграно), доктрины и модификаторы — каждый своей ачивкой с конкретным условием. Профилей нет: прогресс общий на браузер, как и обычные сохранения.

## Где живёт прогресс

Мета-прогресс полностью отделён от `GameState`: `restartGame` (`src/game/slices/gameManagement/helpers/restartGame.ts`) пересоздаёт весь игровой стейт при каждом рестарте, поэтому карьерные счётчики хранятся в собственном модуле `src/game/metaProgress/` со своим ключом localStorage — `star-wanderer-meta-progress`, версионированная обёртка `{ version, state }` по образцу `src/game/saves/migrations.ts`.

- `types.ts` — `MetaProgressState` (карьерные счётчики и разблокировки) и `RunSummary` (снимок одного забега).
- `storage.ts` — `loadMetaProgress`/`saveMetaProgress` + `normalizeMetaProgress`, которая на любом мусоре/повреждённых данных подставляет дефолты, убирает дубликаты и отфильтровывает id, которых больше нет в текущих таблицах ачивок/кораблей.
- `store.ts` — модульный снэпшот + pub/sub (`subscribeMetaProgress`/`getMetaProgressSnapshot`) и единственная точка записи `recordRunResult`.
- `runSummary.ts` — `buildRunSummary(state, outcome)`, чистая функция, строит `RunSummary` из финального `GameState`.
- `achievements.ts` / `shipUnlocks.ts` — таблицы условий (см. ниже).
- `useMetaProgress.ts` — обёртка `useSyncExternalStore` для UI; в отличие от `WelcomeTutorial.tsx`/`GalaxyMap.tsx` в этом кодбейзе подписка настоящая, а не заглушка — прогресс может обновиться в этой же вкладке, пока модалка новой игры уже смонтирована.

`recordRunResult` вызывается из обеих точек конца забега — `checkGameOver.ts` (поражение) и `triggerVictory.ts` (победа) — то есть каждый забег даёт ровно одну сводку, независимо от исхода. Идемпотентность обеспечивает поле `runId` (генерируется `crypto.randomUUID()` в `restartGame`, живёт весь забег, попадает в `RunSummary`): `recordRunResult` сверяет `summary.runId` с `lastRecordedRunId` из мета-стора и молча выходит при совпадении, так что случайный повторный вызов (hot-reload, будущий рефакторинг) не задваивает счётчики.

Два счётчика существуют только в `GameState`, не восстановимы из его финального снимка и обнуляются рестартом: `bossesDefeatedThisRun`, `maxEnemyThreatDefeatedThisRun` (оба — `playerVictory.ts`, инкремент/максирование при каждой победе в бою). Всё остальное `RunSummary` читает из уже существующих полей (`credits`, `turn`, `completedContractIds`, `raceReputation`, `artifacts`, `galaxy.sectors[].visited/tier`, `emergencyFuelStationIds`, `crew`).

## Разблокировка кораблей

По общему прогрессу, не по конкретным условиям — в отличие от доктрин/модификаторов.

| Шаблон | Сложность | Условие |
|---|---|---|
| Экспедиционный (`explorer`) | лёгкий | доступен сразу |
| Грузовой (`trader`) | лёгкий | доступен сразу |
| Научный (`scientist`) | средний | завершить ≥1 забег (любой исход) |
| Ремонтный (`engineer`) | средний | завершить ≥1 забег (любой исход) |
| Ударный (`fighter`) | сложный | ≥1 победа за карьеру |
| Оружейный полигон (`dev_arsenal_fixture`) | — | вне прогрессии, гейтится только `NODE_ENV=development` |

Правила — `shipUnlocks.ts` (`SHIP_UNLOCK_RULES`, ключ = id шаблона). Id без правила в этой таблице по умолчанию считается разблокированным — это осознанно защищает `dev_arsenal_fixture` (и любой будущий шаблон вне прогрессии) от попадания в «заблокировано» по умолчанию.

## Таблица достижений (16)

Каждая ачивка 1:1 соответствует id из `LAUNCH_MODIFIERS` (`src/game/constants/launchModifiers.ts`) — `achievements.ts` не дублирует данные модификатора (имя/иконка/эффект), только ссылается на его `id` и добавляет условие разблокировки. Четыре доктрины (`group: "doctrine"`) — более «престижная» ступень, требуют условий за карьеру без исключений; обычные модификаторы — смесь «за забег» и «за карьеру».

- **За забег** — условие проверяется по `RunSummary` одного завершившегося забега.
- **За карьеру** — накопительный счётчик в `MetaProgressState`, физически не может выполниться за один забег.

| id | Тип | Название | Условие | Вид | Исход |
|---|---|---|---|---|---|
| `doctrine_explorer` | доктрина | Путь исследователя | Победить в 2 разных забегах, посетив ≥15 секторов в каждом | за карьеру | только победа |
| `doctrine_boss_hunter` | доктрина | Гроза древних | Суммарно повержено ≥3 боссов за карьеру | за карьеру | любой |
| `doctrine_trader` | доктрина | Деловая хватка | Завершить 2 разных забега с балансом ≥₢3000 | за карьеру | любой |
| `doctrine_exile` | доктрина | Путь изгнанника | Победить в 2 разных забегах, каждый — с враждебной репутацией (≤-50) хотя бы с одной расой | за карьеру | только победа |
| `veteran_crew` | модификатор | Закалённый в боях | Суммарно ≥3 победы за карьеру | за карьеру | только победа |

Пороги — константы в начале `achievements.ts` (`DOCTRINE_REPEAT_TARGET`, `BOSSES_TARGET` и т.д.), не разбросаны по условиям.

### Числовой прогресс

`AchievementDef.getProgress?(lifetime)` возвращает `{ current, target }` только там, где число осмысленно — карьерные счётчики (боссы, победы, контракты, объединения crisis/artifact id, три bespoke-счётчика доктрин `winsWithSectors15Plus`/`runsWithCredits3000Plus`/`winsWithHostileRep`). Условия «за забег» его не задают: дробный прогресс для одноразового события внутри забега не имеет смысла, UI показывает просто «заблокировано» + текст условия.

## UI

`AchievementsPanel.tsx` — общий переиспользуемый компонент (три секции: Корабли / Доктрины / Модификаторы, для каждой записи ✓/🔒, название, условие, прогресс-бар с `current/target` там, где условие карьерное). Не завязан на способ показа — три места его используют:

- **`NewGameSetupModal`** — заблокированные карточки кораблей и кнопки доктрин/модификаторов помечены `disabled`, вместо описания/статов показывают `LockedHint` (🔒 + текст условия из `descriptionKey` + `current/target`, если есть). Точечно, только для того, что реально настраивается в этой модалке. `toggleModifier` дополнительно не даёт включить заблокированный id программно, не только визуально.
- **Экран достижений во время забега** — не вкладка в левой панели (в первой версии Фазы 4 была, убрана после фидбэка пользователя), а `AchievementsDialog.tsx`, открывается кнопкой «🏆 Достижения» в меню (`SaveLoadPanel.tsx`, открывается через «☰» в хедере). Тот же ручной full-screen оверлей, что и `HelpPanel.tsx`.
- **Стартовый экран (`StartMenu.tsx`)** — вкладка «Достижения» в консоли запуска (`ЗАПУСК / ДОСТИЖЕНИЯ / СОХРАНЕНИЯ / НАСТРОЙКИ / УПРАВЛЕНИЕ`, Radix `Tabs`), рендерит `AchievementsPanel` напрямую без обёртки-диалога. Добавлена по фидбэку пользователя, чтобы прогресс был виден до старта забега, а не только через `☰` внутри уже идущей игры.

Все три места читают прогресс через `useMetaProgress()` и перерисовываются вживую при изменении — без перезагрузки страницы и без размонтирования уже открытой модалки/диалога/вкладки.

## Известные ограничения

- **Пороговые значения не откалиброваны реальным плейтестом.** Числа в таблице выше — первая прикидка на основе анализа кода (сколько секторов/боссов/контрактов технически достижимо), не данных о том, как реально играют. Плейтест ещё не проводился на момент Фазы 5; если после него какие-то условия покажутся слишком лёгкими/недостижимыми, править constants в начале `achievements.ts`, `shipUnlocks.ts`, `store.ts` (`EXPLORER_SECTORS_THRESHOLD`, `TRADER_CREDITS_THRESHOLD`) — таблица выше и `check-meta-progress.mjs` придётся обновить вместе с числами.
- `random_starting_tech` считает только `ArtifactRarity === "legendary" | "mythic"`, отдельное булево поле `cursed?: boolean` на артефакте не проверялось на синхронность с `rarity === "cursed"` — см. «Риски» в `META_PROGRESSION_PLAN.md`, если условию когда-нибудь понадобится опираться на `cursed`.
- Суммарный заработанный за карьеру кредит не отслеживается, только баланс на конец забега (`doctrine_trader`) — оприходование всех источников денег потребовало бы хуков в бою/контрактах/торговле вместо одной точки на конец забега.
- Фаза 2.5 подняла `creditDelta` у `stranded`/`damaged_ship`/`weakened_reactor`, но опиралась на качественную оценку «выглядит слабым», не на `check:economy`/`check:income` (те считают баланс обычной игры, не launch-модификаторы отдельно).

## Проверка

`npm run check:meta-progress` покрывает: `mergeUnique` без дублей; `normalizeMetaProgress` не падает на мусоре/частичном вводе и по отдельности сбрасывает в дефолт неверно типизированные/отрицательные/`NaN` поля, фильтрует незнакомые id; идемпотентность `recordRunResult` на повторном `runId`; пороги (off-by-one) всех 16 ачивок и правил разблокировки кораблей; сквозной интеграционный тест через реальный `recordRunResult`.

Меняя пороги, шаблоны кораблей или таблицу ачивок — обновлять `scripts/check-meta-progress.mjs` вместе с кодом, а не только эту таблицу.
