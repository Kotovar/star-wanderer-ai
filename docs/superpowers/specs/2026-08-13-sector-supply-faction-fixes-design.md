# Компактная карта и точные последствия фракционной доставки

**Статус:** согласовано, ожидает плана реализации.

## Цель

Убрать лишнюю высоту у верхнего оверлея карты сектора на широком экране, не смешивать поиск груза с местом сдачи в поставках и обеспечить, что цифры в выборе фракционной доставки совпадают с фактическим результатом.

## Область изменений

### Карта сектора

На `lg` и шире карточка особенности системы располагается в одной строке с карточкой сектора. Внутри сохраняются название, иконка и описание правила. На меньшей ширине обе карточки остаются вертикальной колонкой, чтобы описание не сжималось и не пересекалось со сканером.

### Поставка ресурсов

Для `supply_run` строка `Где сдать` содержит только точку приёма: тип, имя и сектор планеты или корабля-заказчика. Подсказка `Купить на любой торговой станции или найти в другом месте` не повторяется в этой строке: задача уже говорит, что груз нужно найти и доставить.

### Фракционная доставка

В контекст `diplomatic_claim` передаётся локализованное имя расы-заказчика, поэтому `{{sourceRace}}` никогда не остаётся в интерфейсе.

Для варианта «передать местным» прямые последствия фиксированы: местные получают ровно `+4`, заказчик — ровно `−4`. Каждое изменение всё ещё создаёт обычную дипломатическую рябь для остальных рас, но две прямо затронутые расы исключаются из ряби друг друга. Поэтому взаимные отношения заказчика и местных не меняют заявленные цифры, а третьи расы продолжают реагировать на оба решения.

## Реализация

- В `SectorMap` меняется только адаптивная раскладка существующего оверлея.
- В `ContractsList` `supply_run` выводит целевую локацию в `task_where` без текста о покупке.
- `changeReputation` получает необязательный список рас, исключаемых только из вторичного ripple-эффекта. Обычные вызовы не меняются.
- Резолвер фракционной доставки передаёт в каждый из двух вызовов другую сторону выбора как исключение. Окно завершения по-прежнему строится по фактическому снимку репутации.
- Описание механики в `CAMPAIGN_PROGRESSION.md` и `REPUTATION_TRADEOFFS.md` уточняется: прямые две стороны получают ровно заявленные изменения, рябь затрагивает третьи расы.

## Проверка

- Дополнить `check-sector-rules` проверкой desktop-раскладки оверлея.
- Дополнить `check-contract-labels` проверкой: в ветке `supply_run` нет текста поиска груза в `task_where`, а есть цель сдачи.
- Дополнить `check-faction-delivery-choices`: подстановка `sourceRace`, а также реальный расчёт для людей и кристаллоидов даёт ровно `+4` и `−4`; третья раса получает рябь.
- Прогнать затронутые скрипты, `npm run type-check`, `npm run lint`, `npm run build` и `git diff --check`.

## Вне области

- Не меняются вероятность, награды, XP или две опции фракционной доставки.
- Не добавляются новые типы контрактов, экранов или система дипломатии.
