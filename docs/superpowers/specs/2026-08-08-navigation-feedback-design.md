# Navigation and Expedition Feedback Design

## Goal

Make saved-game loading, station module discovery, expedition scans, mutation naming, and oxygen-risk hiring clearer without changing the underlying game balance.

## Scope

- The start-menu tab is labelled `ЗАГРУЗИТЬ` in Russian and `LOAD` in English. Occupied save slots have a clear hover and keyboard-focus state; empty slots remain visually disabled.
- Navigator gets a `modules` category with a module type filter and an exact module-level filter. It searches the deterministic inventory generated by `generateStationItems` and returns only visited stations, so results reflect stock the player has actually seen.
- Expedition scan controls state their rules before activation:
  - scientist scan: one charge per scientist, only a reachable neighbouring unrevealed tile;
  - orbital scan: one charge from an operational ship scanner, any unrevealed tile.
  Neither scan spends AP or resolves a tile.
- Mutation `regeneration` is named `Мутация: Клеточное восстановление` / `Mutation: Cellular Recovery`; its id and effects do not change.
- Hiring an oxygen-breathing candidate beyond life-support capacity returns a structured warning from the shared hiring action. `CrewTab`, used by both stations and friendly ships, shows a `GameDialogContent` warning and repeats the action only after confirmation. No native browser confirmation remains.

## Architecture

`getNavigatorResults` already operates over known locations and `generateStationItems` already supplies deterministic shop stock to `StationPanel`. The navigator imports that generator, adds only module-match results, and reuses its existing result cards and map markers.

The hiring decision remains in `hireCrew`, which keeps validation and state mutation authoritative. Its result distinguishes a completed hire from an oxygen confirmation requirement; `CrewTab` owns the one reusable modal and forwards the confirmed retry through each existing parent callback.

## User-facing copy

All new labels, scan explanations, module-result details, confirmation title/actions, and mutation name are added to both locale catalogs. Copy calls the progression number a `level`, not a `tier`, except where it is specifically a sector tier already established in the UI.

## Error handling and compatibility

The confirmation retry re-runs existing credit, capacity, reputation, and oxygen checks, so a stale dialog cannot make an invalid hire. Stations lacking saved configuration continue to use the generator's existing defaults. Old saves need no migration because no persisted field changes.
